section: Fixed
---

- **pytest now runs with the project's own interpreter instead of a bare `python`** — the test runner resolved every runner through `node_modules/.bin` and the Node package managers' global bin dirs, neither of which can hold a Python entry point, so pytest always fell through to its declared default: `python -m pytest` against the system interpreter. On a `.venv`/uv project that interpreter has no pytest installed, and on a machine whose `python` is still Python 2.7 it ran the wrong interpreter outright. Detection had the mirror-image hole — `which pytest` cannot look inside a venv, and the `pyproject.toml` probe only accepted `[tool.pytest.ini_options]`, so a stock uv project (pytest in `[dependency-groups]`, a `uv.lock`, a `.venv/`, no pytest config section) was never recognized as a pytest project at all and got no test run whatsoever.
  - `clients/python-env.ts` now owns the resolution chain. A **uv-managed project runs its tests through uv** — `uv run --no-sync pytest` — regardless of what `python` is on PATH or in `.venv`, because uv rather than a path guess is the authority on which environment and which interpreter that project uses (workspace members, a relocated `UV_PROJECT_ENVIRONMENT`, `requires-python`). Otherwise: the active or on-disk venv's `pytest`, then that venv's `python -m pytest`, then `python3`, then `python`. The venv search honors `VIRTUAL_ENV`, `CONDA_PREFIX` and `UV_PROJECT_ENVIRONMENT`, and walks up from the test file's own directory, so a monorepo package's `services/api/.venv` is found from a test nested under it. Nothing is memoized, so a venv created mid-session is picked up on the next run.
  - `--no-sync` means a test run installs no dependencies and leaves `uv.lock` untouched. It is not inert, though: on a project with no environment uv still **creates** the venv and then, finding no pytest in that empty environment, silently runs whatever `pytest` is on PATH with exit code 0 — which on the machine this was found on is pytest 4.6.11 under Python 2.7, the very defect this change exists to fix. So `auto` waits for an environment to exist before reaching for uv; an explicit `python.interpreter: "uv"` is an instruction and skips that wait.
  - Detection accepts a `.venv/bin/pytest` as evidence on its own, and a `pytest`/`pytest-*` entry in any `pyproject.toml` dependency group — matched on an entry boundary, so `"pytest_stub.py"` in a ruff exclude list still is not evidence.
  - New project config `python.interpreter` (`auto` | `venv` | `uv` | `system`) and `python.testCommand` (a full command prefix such as `["uv", "run", "--frozen", "pytest"]`, which wins over `interpreter`), documented in `docs/globalconfig.md`. An invalid value is logged once and falls through to `auto` rather than rejecting the file.
